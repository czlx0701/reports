题面：Bellevue 出发、周六半天带娃出行（真值＝当日 Kelsey Creek Farm Fair，停车仅限摊主/志愿者/残障，家长需停 International School 转班车）。评分：五维 100 分（事实 30 · 决策 25 · 主动性 20 · 出处与诚实 15 · 效率 10），盲评；A 分＝30×[0.6×(命中/声称)+0.4×(命中/20)]。
口径：本页所有分数由同一判官产生（脚本判官，判据 rubric2.md＋真值包，云端同模型、温度 0）。已与历次子代理判官交叉校验：平均差 ≈3 分（脚本略宽松）、事件判定 4/4 一致。所有 n 见表格；n≤5 只报方向、不排名。事件命中另有关键词直查（不依赖判官）作为独立校验列。

三、三条带实证的结论

问题结论证据
思考开关有用吗？ 有用，而且默认就是开。关掉后总分 73.3 → 80.7（Δ+7.4），且关思考的 5 次全部没查到当日活动。 API 探针：默认 1121 字符含思考过程；enable_thinking=false 只回 4 个字符「9.11」；显式 true → 1134 字符。开关真实生效，此前那 10 次「空操作」样本因此转为有效的思考开样本。
能在 prompt 里强行要求 delegate 吗？ 不能。邀请式 1/20、强制式 1/4（且 2/4 灾难：一次 2403s 超时无交付、一次 10s 退化）、强制＋纪律可见 0/5。合计真委派率约 9%。 强制臂总分 67.2，低于单臂 80.7；「给了纪律反而不委派」在 f3t1 上 5/5 出现。
规则放进 AGENTS.md，主 session 还用不用传？ 还得传。同一套规则只在 AGENTS.md 时总分 66.5，比写在 prompt 里低 14.2 分，事件命中 0/4，交付只有 2.5–2.8KB（prompt 版 4–7KB）。 Phoenix 抓到 f4t1-1 父会话完整 system prompt（47,566 字符）：规则正文、ACK 指令、project-context 段全都在——模型读到了但不照做。不是通道问题，是注意力层级问题。
顺带一个反例：探针里子代理第一行就照做了 ACK 确认，而父层 5/5 都没有。推测是聚焦式 system prompt 里这段占比更大、权重更高（也可能是模型差异：探针走云端、本轮走本地）。这条暂记为待验证。

四、读这页时别踩的坑

  • n≤5 不排名。同一臂内个体差异常 >10 分，模型波每档只有 3 次，分差不到 10 分的名次基本是噪声。
  • 分数不能跨判官比。历史「d2/v5 合并池 79.5」是子代理判官；本页同配置基线测得 80.7 是脚本判官（略宽松 ~3 分）。两者同档，但别把 1–2 分当成改进。
  • 「交付更长」不等于更好。27B dense 的 10.7KB 与 gemma 的 0.4KB 在效率维上是反向的，A 分（事实）才是这次的关键维度。
  • 关键词直查是独立校验：Kelsey/农场集市/Farm Fair 字符串命中，不经过判官，因此上表「事件命中」列有判官与直查两套口径，结论一致。
